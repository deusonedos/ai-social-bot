# AI Social Bot — Project Specification

## 1. Идея проекта

Создать бесплатного AI-бота, которого можно использовать сразу в нескольких каналах:

- Telegram — личные сообщения и групповые чаты.
- Threads — пользователь тегает AI-аккаунт и получает ответ.
- Instagram — пользователь обращается к AI через комментарии/упоминания.

Основная идея: один AI-движок обслуживает все платформы, а пользователю не нужно регистрироваться в отдельном сервисе.

Пример:

> @MyAI реши эту задачу

или пользователь прикрепляет фотографию:

> @MyAI реши

Бот распознаёт изображение, решает задачу и публикует ответ обратно.

---

## 2. Главные принципы

1. Пользовательский интерфейс максимально простой.
2. Пользователь не должен знать, какая модель работает внутри.
3. Контекст каждого чата/диалога полностью изолирован.
4. Используются бесплатные модели OpenRouter там, где это возможно.
5. Архитектура должна позволять позже подключить платные модели без переписывания проекта.
6. Один backend обслуживает Telegram, Threads и Instagram.
7. При недоступности одной модели система автоматически может переключаться на другую.

---

## 3. Архитектура

```text
Telegram ───────┐
                │
Threads ────────┼──> Backend API ──> Context/Memory ──> Model Router ──> OpenRouter
                │                                      │
Instagram ──────┘                                      ├── Text model
                                                       └── Vision model
                                                              │
                                                              ↓
                                                    Ответ пользователю
```

### Основные компоненты

- **Platform adapters**
  - Telegram adapter
  - Threads adapter
  - Instagram adapter

- **Backend**
  - принимает события;
  - определяет пользователя и чат;
  - нормализует сообщения;
  - управляет контекстом;
  - вызывает AI;
  - отправляет ответ обратно.

- **Context/Memory**
  - хранит историю;
  - разделяет контексты;
  - создаёт краткие summaries;
  - выбирает сообщения, которые нужно передать модели.

- **Model Router**
  - выбирает подходящую модель;
  - отдельно обрабатывает текст и изображения;
  - умеет переключаться на резервную модель.

- **Database**
  - PostgreSQL.

---

## 4. Изоляция контекстов

Критически важно: один чат никогда не должен видеть историю другого.

Например:

```text
Telegram group 100
  └── context A

Telegram group 200
  └── context B

Threads user 300
  └── context C

Instagram user 400
  └── context D
```

В базу каждое сообщение записывается с идентификаторами:

- platform
- conversation_id
- user_id
- message_id
- role
- content
- timestamp

При запросе модели backend получает историю только соответствующего `conversation_id`.

OpenRouter сам не должен считаться системой памяти проекта. Память и выбор контекста реализуются на нашем backend.

---

## 5. Контекстное окно

Модель не должна получать бесконечную историю.

Рекомендуемый подход:

```text
Старые сообщения
       ↓
   Summary
       +
Последние сообщения
       ↓
   AI model
```

Пользователь при этом ничего не делает вручную.

Например:

```text
Summary:
Пользователь решает задачи по математике.
Он предпочитает объяснение пошагово.

Последние сообщения:
User: А если x = 7?
Bot: Тогда подставляем...
User: А почему здесь плюс?
```

Для пользователя это выглядит как обычный продолжающийся разговор.

---

## 6. Работа с изображениями

Бот должен принимать изображения.

Сценарий:

```text
Пользователь отправляет фото
        ↓
Backend получает файл
        ↓
Определяет, что запрос vision
        ↓
Отправляет изображение + инструкцию в vision-модель
        ↓
Получает решение
        ↓
Отправляет ответ пользователю
```

Примеры:

- фотография математической задачи;
- фотография текста;
- скриншот;
- схема;
- таблица;
- учебное задание.

Важно выбирать только актуальные бесплатные vision-модели OpenRouter с поддержкой image input.

---

## 7. Работа с текстом

Обычный текстовый запрос:

```text
User:
Объясни теорему Пифагора простыми словами
```

Backend:

```text
message
  ↓
context
  ↓
text model
  ↓
response
```

## 9. Видео

Видео не обязательно отправлять целиком непосредственно в LLM.

Можно сделать:

```text
Video
  ↓
Extract frames
  ↓
Extract audio
  ↓
Speech-to-text
  ↓
Vision + text processing
  ↓
AI response
```

Видео лучше добавить после запуска основной версии.

---

## 10. Model Router

Не привязываться к одной модели.

Пример:

```text
Incoming request
       ↓
Есть изображение?
   /         \
 Да           Нет
 ↓             ↓
Vision       Text
model        model
 ↓             ↓
Ошибка?      Ошибка?
 ↓             ↓
Fallback     Fallback
```

Конфигурацию моделей хранить отдельно от основной бизнес-логики.

Например:

```text
TEXT_MODEL_PRIMARY
TEXT_MODEL_FALLBACK
VISION_MODEL_PRIMARY
VISION_MODEL_FALLBACK
```

Так смена модели не требует переписывать backend.

---

## 11. OpenRouter

OpenRouter используется как единая точка доступа к моделям.

Backend не должен напрямую зависеть от конкретной модели.

Логика:

```text
Backend
   ↓
OpenRouter API
   ↓
Selected model
```

API-ключ хранить только на сервере.

Никогда не отправлять OpenRouter API key пользователю и не хранить его в frontend-коде.

---

## 12. Telegram

Telegram — первая платформа для MVP.

Функции:

- личный чат;
- групповые чаты;
- ответы на сообщения;
- фотографии;
- текст;
- позже голосовые;
- позже документы/PDF.

### Поведение в группе

Бот не обязан отвечать на каждое сообщение.

Рекомендуемый режим:

```text
@MyAI вопрос
```

или reply на сообщение бота.

Это снижает количество запросов и стоимость инфраструктуры.

## 14. Instagram

```text

        ↓

        ↓

        ↓
```

На первом этапе Instagram можно реализовать только как текстовый канал.

После стабилизации добавить обработку изображений, если конкретный API-сценарий и разрешения это поддерживают.

## 16. Безопасность

Обязательно:

- API-ключи только в environment variables;
- webhook secrets;
- проверка входящих webhook;
- rate limiting;
- защита от спама;
- ограничение размера файлов;
- ограничение длины сообщений;
- логирование ошибок;
- отдельные права для администратора;
- защита от prompt injection там, где это необходимо;
- фильтрация потенциально опасного контента.

---

## 17. Ограничение бесплатного использования

Даже если AI-модели бесплатные, инфраструктура проекта может стоить денег.

Поэтому сразу предусмотреть:

```text
user/group
    ↓
daily request limit
    ↓
rate limiter
    ↓
AI
```

Лимиты можно сделать мягкими.

Например:

- ограничение частоты сообщений;
- ограничение размера изображения;
- ограничение количества AI-запросов за короткий период.

## 18. Вирусность

Главная цель — сделать использование бота саморазвивающимся.

### Механика 1 — mention

```text
@MyAI реши эту задачу
```

Человек автоматически показывает бота всем участникам обсуждения.

### Механика 2 — Reply

Пользователь отвечает на сообщение:

```text
@MyAI объясни
```

### Механика 3 — групповые функции

Добавить:

- мини-олимпиады;
- викторины;
- соревнования;
- рейтинги;
- достижения;
- ежедневные задачи;
- «задача дня».

### Механика 4 — shareable answers

Ответ должен быть коротким и понятным, чтобы его хотелось переслать.

---

## 19. Монетизация

Базовая версия может оставаться бесплатной.

Варианты монетизации:

1. Небольшая ненавязчивая реклама.
2. Партнёрства с образовательными сервисами.
3. Платные расширенные функции позже.
4. Premium-модели как дополнительная опция.
5. Корпоративные версии для школ/компаний.

Реклама не должна мешать основному использованию.

- Текстовые запросы.

- PostgreSQL.

## 23. Пример обработки сообщения

```text
1. Пользователь пишет в Telegram:
   "@MyAI реши x² - 5x + 6 = 0"

2. Telegram отправляет update на webhook.

3. Backend определяет:
   platform = telegram
   conversation_id = конкретная группа

4. Backend загружает:
   - summary этой группы;
   - последние сообщения этой группы.

5. Backend определяет тип запроса:
   text.

6. Model Router выбирает бесплатную text model.

7. Backend отправляет запрос через OpenRouter.

8. Получает ответ.

9. Сохраняет сообщение и ответ в PostgreSQL.

10. Отправляет ответ обратно в Telegram.
```

## 24. Главная идея проекта

Не делать «ещё один ChatGPT».

Сделать:

> **AI, которого можно просто позвать прямо там, где люди уже общаются.**

Пользователь не должен открывать отдельное приложение.

Он просто пишет:

```text
@MyAI помоги
```

и получает ответ.

Telegram, Threads и Instagram — это интерфейсы.

OpenRouter — слой доступа к моделям.

Backend — мозг продукта.

PostgreSQL — память.

Model Router — механизм выбора AI.
